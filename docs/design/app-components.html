App components & screen patterns

The composites that assemble whole screens — the layer above components.html. A standard component answers “what does one control look like in every state”; a composite answers “how is a screen laid out, and what chrome does it carry”. This file is built exclusively from the tokens and rules of design-specs.html and composes the standard components — it introduces no new visual values.

Order is deliberate: layouts first (§1–2) because screen architecture is the highest-leverage shared surface across paisa trak, ntele and roadpulse — then the chrome pieces (§3–4), overlays (§5–6), and flow composites (§7–12).

How to read this file Composites render inside phone frames at proportions native apps use. The frame itself — status bar, home indicator, device radius — is presentation, not spec; only the composite inside the frame is specified. As everywhere in this set, every specimen is rendered with the kala tokens themselves and the header toggle flips the whole page.

Decision rule: chrome answers two questions — where am I (title) and what can I do here (actions). A screen that needs neither is pattern 1; one that needs only “where am I” is 2 or 6 (6 if pushed onto a stack); peer destinations add 3/4; tasks that must finish are 5 or 7.
2.1 · Fixed chrome, scrolling body Header and tab bar never scroll — only the body does. The one sanctioned exception is the collapsing large-title header (§3.1), which trades height for context as the body scrolls, and translucent tab-bar blur when content scrolls under it. Anything else is a layout bug.

4.1 · Tab count and order Three to five destinations, five is the ceiling. Order: most-used first, Profile last. Destinations are named by what they show, not verbs (“Activity”, not “Manage”). Each tab remembers its own scroll position; switching tabs never animates content between destinations.

5.1 · Sheet vs dialog vs menu Quick task with context → sheet. Confirmation or alert that must be answered → dialog (§6). Command list anchored to a control → menu (components §17); the same list presented globally becomes a peek sheet (action-sheet). A side-anchored sheet (navigation drawer) is a future variant of this component, same contract mirrored — deferred, see provenance.

Governance Same contract as the rest of the set: this file may only reference tokens and rules defined in design-specs.html, and composes components specified in components.html. A composite introducing a new color, radius, duration, spring, or size fails spec review. Phone frames, status bars and home indicators are page presentation and carry no spec weight.
