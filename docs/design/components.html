Standard components + states

The kala-ui standard component catalog. Every specimen below is rendered live from the foundation tokens (design-specs.html) — no color, radius, or duration appears here that the foundation does not declare. Each component carries its variant matrix, its state contract, and its slot surface (tier 3).

Variant axes transcribed from the shipped web implementation (packages/react/src/config/button.ts & co.); the state columns define what both web and React Native builds must implement. Sizes: xs 28 · sm 36 · md 40 · lg 44px — native touch floors per foundation §8.1. Inventory gap-checked against MUI, Ant Design, shadcn/ui, Mantine, RN Paper, Gluestack and Tamagui.

Scope & deferral §

What this catalog deliberately excludes, and where it lives instead.

Excluded from the standard kitWhy / where instead
Sheets, headers, tab shells, screen layoutsApp-level composites — app-components.html
Calendar, combobox, command palette, tree, data-table, chartsWeb-only today; enter the native catalog only when an app needs them (then as native-first designs, not ports)
Dialog / AlertDialog primitivesSpecified in app-components.html §together with sheets — on native the modal surface IS the sheet family
Rating, copy buttonWeb lib ships them; no app use case yet — enter the catalog when an app needs one (OTP is an Input composition, §2)
Governance — a new state or variant lands here before it lands in code; a component may not ship a state not in this matrix. Slot surfaces above are the complete tier-3 surface: anything beyond them is a library change, not an app override.
